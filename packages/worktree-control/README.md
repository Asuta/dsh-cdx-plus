# 工作树管理

为 DSH 对话提供独立的 Git 工作树管理面板。创建或切换工作树时，只更新当前会话的工作目录，因此对话历史保持连续。

## 功能

- 从当前提交或本地/远端分支创建 detached 工作树，也可以同时新建分支。
- 助手回复下方的原生分支按钮会打开两个选项：在当前工作区沿用原生方式创建对话分支，或立即创建新工作树并打开分支对话。新工作树默认复制源目录的未提交改动；当前目录不是可用 Git 工作树、源对话运行中或只读时会说明原因。
- 新对话通过设置弹层选择是否创建工作树、基础分支和本地环境；工作树在首条消息发送时创建，详细设置继续使用右侧面板。
- 侧边栏为所有 Git 附加工作树中的对话显示分叉标记，依据对话当前目录更新。
- 配合侧边对话插件，转为独立会话后继续归属原项目并共用原工作树，登记为另一条工作树会话。两个会话共享文件，归档其中一个不会清理仍被另一个使用的工作树。
- 选择把当前工作树的暂存、未暂存和未跟踪改动复制到新树；源工作树不被修改。
- 按 .worktreeinclude 的 .gitignore 风格模式复制忽略文件，并自动带入被忽略的 AGENTS.override.md；不覆盖目标已有文件，拒绝符号链接和越界路径。
- 每个项目可保存、编辑、删除多份本地环境配置，设置默认环境或为单个对话切换；可将 .codex/environments/environment.toml 导入为可编辑副本。
- 环境配置可包含新工作树创建后的 setup 脚本和手动执行的项目操作。初始化失败时仍会进入新工作树并发送首条消息，详细页会显示失败原因；切换已有对话的环境不会自动重跑脚本。
- 在同一对话中切换本地目录或其他 Git 工作树，也可把成果交接到本地或该对话之前使用的工作树。
- 查看差异，按文件暂存、取消暂存或丢弃；提交已暂存内容、推送分支，并通过 GitHub CLI 打开 PR 创建流程。
- 归档前创建可恢复快照；恢复时把快照内容还原为暂存改动。
- 归档已加载的对话时，自动快照并清理不再被其他未归档对话使用的关联工作树；固定的工作树保留。未加载对话关联的旧树由保留数量策略后续清理。
- 每个仓库可设置自动保留数量（默认 15，0 表示关闭）。自动归档会跳过固定、当前或活动对话正在使用的工作树。

## 环境命令

对话右上角“变更”旁的运行菜单列出当前环境的手动命令，可从“切换环境”更换此对话的环境，或从“管理环境”进入配置页。无 Git 工作目录时不显示此入口。切换环境不会自动重新初始化。

快捷菜单、详细页的手动操作及新工作树的自动初始化都会打开 DSH 内置侧栏终端，在对应工作树目录实时显示命令、输出和执行结果。同一命令运行中再次点击会定位到原终端，不会重复启动；结束后保留日志，新一次执行使用新的终端，可关闭已完成的终端释放名额。支持终端 Ctrl+C 和菜单中的“停止”；关闭执行终端也会停止对应命令。手动操作可用于持续运行的开发服务，初始化脚本最多运行 10 分钟。

需要启用 DSH 内置终端，并在本机 PATH 中提供 Node.js。实际脚本继续遵守对话的权限限制；初始化会等待终端连接后才开始，45 秒内无法打开时明确报错并保留已创建的工作树。执行期间不能通过本插件修改同一工作树的 Git 状态或切换、清理工作树。

“手动操作”的名称与命令分开编辑，命令框支持 Enter 换行、粘贴多行脚本并保留换行。多条命令共享同一脚本作用域，在当前工作树目录执行。
保存时自动忽略名称和命令都为空（含纯空白字符）的操作；只填一项时会标明操作序号、提示缺少的字段并聚焦输入框。保存失败保留已填写内容和原配置。

初始化脚本和手动操作默认遇到错误便停止后续执行。Windows 使用 PowerShell，并检查 Git 等外部程序的非零退出码；其他平台使用 `sh -e`。显式条件判断、错误捕获和管道仍遵循对应 shell 的控制规则。停止不会撤销先前已经成功的命令。

## 安装

本插件随 dsh-plugin-lab 开发，使用本地目录安装：

~~~powershell
dsh plugin --profile desktop add <插件目录>
~~~

安装后刷新 DSH 网页版；桌面版需要由用户自行完成最终验收。

## 数据与安全边界

- 工作树默认位于仓库主工作树的 .agents/worktrees/；面板内可设置其他绝对路径，仅影响之后创建的工作树。
- 插件状态和归档 Git 引用保存在仓库的 Git common directory 下 dsh-worktree-control/ 与 refs/dsh-worktree-control/archive/。
- 环境配置、默认项、新对话草稿与对话选择记录保存在同一个仓库的 Git common directory 下，所有附加工作树共享。
- 快照保存 Git 已跟踪改动、非忽略未跟踪文件、未推送提交可达的历史，以及 .worktreeinclude 明确列出的文件。其他被忽略文件不会进入快照。
- 含子模块或未解决冲突的工作树不能归档。归档、恢复和删除快照均在操作前验证目标。
- 初始化脚本只在用户勾选/点击后运行；它在新工作树目录执行。创建 PR 需要已安装并登录 GitHub CLI（gh）。
- 交接复制源目录相对共同祖先的成果，源目录和目标分支引用保持原样。目标必须没有未提交改动且能无冲突应用，带入内容作为暂存改动。
- 目录切换使用 DSH 原生工作目录服务，不更换会话，也不重建右侧标签；已有进程继续使用原来的目录。
- 快照不会保留暂存与未暂存的原始分界。恢复后使用 detached HEAD；需要推送时可在面板中创建分支。
- 自动保留无法确认安全时只显示提示，不强制删除工作树。
